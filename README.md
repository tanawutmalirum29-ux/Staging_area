# Staging_area

พื้นที่ทำงาน **สำรองแบบชั่วคราว** ขององค์กรสำหรับหลายโปรเจกต์ เมื่อช่องทางพัฒนาปกติมีข้อผิดพลาดทางเทคนิคและย้ายงานมาได้ตามสิทธิ์ที่อนุญาต

**กฎกลาง:** [appointment-CEO/RULES.md](https://github.com/tanawutmalirum29-ux/appointment-CEO/blob/main/RULES.md) ข้อ 5.1 และ [COMMANDS.md](https://github.com/tanawutmalirum29-ux/appointment-CEO/blob/main/COMMANDS.md)

## วิธีใช้

1. ยืนยัน `PROJECT_REPO`, Source Branch/SHA, Issue, เจ้าของไฟล์, สิทธิ์ และสาเหตุที่ต้องใช้พื้นที่สำรอง
2. สร้าง Branch ของงาน `stage/<project>/<issue-or-mission>`; ห้ามปะปนสองโปรเจกต์ใน Branch เดียว; `main` ของรีโปนี้เก็บเฉพาะคู่มือ
3. เก็บ Source ที่มีสิทธิ์ใช้, Patch, Tests และ `STAGING_MANIFEST.md` ของ Branch นั้น ระบุชื่อโปรเจกต์, Source SHA, เวลา, เจ้าของงาน, ไฟล์เปลี่ยน, dependencies, สถานะ CI/QA และแผนส่งกลับ
4. ทดสอบแบบจริงและแจ้งผล FAIL/NOT_RUN ตามจริง; ห้ามอ้างว่า Commit ในรีโปนี้เท่ากับส่งมอบผลิตภัณฑ์
5. เมื่อช่องทางหลักเปิดใช้ได้โดยถูกต้อง ให้นำการเปลี่ยนแปลงกลับไป PR ใน `PROJECT_REPO`, ผ่าน CI และ Independent QA จึง Merge ไป `PROJECT_REPO/main`
6. หลังส่งมอบและตรวจผลจริง ลบ Branch ชั่วคราวที่ไม่มีคนใช้ตาม PF; ไม่ลบ/Force Push งานของผู้อื่น

## การแยกประเภทปัญหา

- **ชั่วคราว:** timeout, DNS, 5xx, 429 ที่รอได้, stale SHA/conflict — วินิจฉัย/Retry จำกัดก่อนใช้พื้นที่สำรอง
- **โค้ด/ทดสอบล้ม:** แก้สาเหตุในไฟล์ของผู้รับผิดชอบ ไม่ข้าม QA เพื่อให้ดูเขียว
- **ปฏิเสธสิทธิ์/ความปลอดภัย:** ห้ามนำการเขียนที่ถูกบล็อกไปทำผ่านรีโปนี้หรือช่องทางอื่นเพื่อเลี่ยงข้อจำกัด; ทำได้เฉพาะงานอ่าน/วิเคราะห์/สำเนาท้องถิ่นที่อนุญาตและให้ผู้มีสิทธิ์ตรวจสอบ

**ZIP เป็นทางเลือกสุดท้าย** เมื่อช่องทางเขียนที่อนุญาตใช้ไม่ได้จริง โดยต้องมี Patch/Manifest/Checksum/คำสั่ง Dry-run และผลทดสอบตรงตามจริง ห้ามนำ Secrets หรือข้อมูลที่ไม่มีสิทธิ์เผยแพร่ขึ้นรีโปสาธารณะ
